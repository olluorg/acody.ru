Как выбрать задачу для технического собеседования?

SeniorИстории из опыта
Ещё спрашивают так:
  • Какие задачи давать на собеседовании?
Коротко

Задача проверяет то, что нужно для роли: для бэкенда — проектирование API и данных, работа с кодом, отладка; не загадки и не редкие факты. Она масштабируется: базовая часть решается за 15–20 минут, дальше — усложнения для сильных кандидатов. Одинакова для всех кандидатов на позицию, опробована на коллегах, у неё есть критерии оценки и типичные ответы по уровням. Условие понятное, подсказки — заранее продуманы.

  • Близость к реальной работе важнее «интересности»
  • Утечка задачи в интернет — повод сменить, а не запрещать готовиться
  • Проверять рассуждения, а не только итоговый ответ

А ещё Хорошая задача даёт разницу между junior, middle и senior на одном условии

Подробно

Пример: «Сервис принимает заказы, иногда клиент отправляет один заказ дважды. Как сделать, чтобы дублей не было?»

  • базовый уровень — уникальный ключ, проверка в базе;
  • средний — ключ идемпотентности, гонки при одновременных запросах;
  • сильный — повторы между сервисами, очередь, хранение ключей, срок жизни.

Проверка задачи: провести на трёх коллегах разного уровня и убедиться, что задача их различает.

Что хотят услышать

  • Связь с ролью и реальной работой.
  • Масштабирование усложнениями.
  • Одинаковость и опробованность.
  • Критерии по уровням.

Проверьте себя

Один верный вариант. Подумайте, потом откройте ответ.

Показать варианты и ответ
  • ✗Логические загадки лучше всего показывают инженера
  • ✗Каждому кандидату — новая задача, придуманная накануне, чтобы ответ нельзя было подготовить
  • ✗Главное — проверить знание редких фактов о языке
  • ✓Задача, близкая к работе, с усложнениями, одинаковая для всех и с критериями
