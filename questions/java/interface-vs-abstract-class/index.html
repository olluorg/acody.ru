Чем интерфейс отличается от абстрактного класса и что изменили default-методы?

MiddleООП

  • Интерфейс или абстрактный класс — как выбирать?
  • Чем интерфейс отличается от абстрактного класса?
  • Интерфейс или абстрактный класс: как выбираешь и что изменили default-методы?
Коротко

Интерфейс — контракт: класс может реализовать много интерфейсов, состояния (полей экземпляра) нет. Абстрактный класс — общая база с состоянием, конструктором и частичной реализацией; наследуется один. default-методы (Java 8) дали интерфейсам код для эволюции API, но не состояние.

  • Нужен контракт для разных иерархий — интерфейс
  • Общий код с состоянием для родственных классов — абстрактный класс
  • На практике чаще интерфейс плюс, при нужде, абстрактная базовая реализация (AbstractList)

А ещё В интерфейсах есть static и private-методы (Java 9), поля — только константы

Подробно

наследованиемного интерфейсоводин класс

конструкторнетесть

модификаторы доступаметоды public (кроме private)любые

Когда интерфейс: нужен контракт, который могут реализовать классы из разных иерархий (Comparable, Runnable, Repository); нужна множественная «роль». Хорошо мокается в тестах.

Когда абстрактный класс: у родственных классов общее состояние и код, работающий с ним; нужен конструктор с проверками; нужны protected поля и методы.

Что изменили default-методы. В интерфейс теперь можно добавить метод с реализацией, не сломав существующие реализации — так в Java 8 появились Collection.stream() и Iterable.forEach(). Но состояния у интерфейса нет, поэтому default-метод может опираться только на другие методы интерфейса. Конфликт одинаковых default-методов из двух интерфейсов класс обязан разрешить сам.

Частый идиом JDK: интерфейс List + AbstractList с общей реализацией + конкретные классы.

Что хотят услышать

  • Различия по наследованию, состоянию, конструктору.
  • Критерий выбора.
  • Роль default-методов и их ограничение.

Частые ошибки

  • Считать, что интерфейсы не имеют реализации (есть default-методы).
  • Думать про множественное наследование классов.
