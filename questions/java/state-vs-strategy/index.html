State и Strategy структурно почти одинаковы. Что их различает?

MiddleПаттерны проектирования
Коротко

Кто управляет подстановкой: стратегию выбирает клиент снаружи, и она обычно не меняется; состояние объект меняет сам в ответ на события, и переходы — часть его логики.

  • State: заказ «новый → оплачен → отправлен», у каждой фазы своё поведение
  • State заменяет разросшиеся switch по статусу
  • В современной Java — enum с методами или sealed-иерархия

А ещё Для сложных процессов — машина состояний (Spring Statemachine)

Подробно

Оба делегируют работу подставляемому объекту, поэтому по структуре неразличимы. Разница в намерении: стратегия — взаимозаменяемый алгоритм, выбранный снаружи; состояние — фаза жизненного цикла, и переходы между фазами составляют часть логики самого объекта. Практическое применение State — рабочие процессы со статусами (заказ: новый → оплачен → отгружен), где иначе получается разбухающий switch по статусу в каждом методе.

Что хотят услышать

  • Различие по намерению и управлению.
  • Пример State.

Частые ошибки

  • Пытаться развести паттерны по механизму — он у них общий.
  • Реализовывать State там, где хватает enum со статусом и пары проверок.
