Почему паттерн Builder особенно удобен при создании неизменяемых объектов?

MiddleПаттерны проектирования
Коротко

У неизменяемого объекта без билдера два плохих варианта: сеттеры (и он уже изменяем) или конструктор с длинным списком однотипных аргументов. Builder собирает состояние по именованным шагам, проверяет все инварианты в build() и отдаёт готовый неизменяемый объект.

  • Нет «полусобранного» объекта, видимого другим
  • Необязательные параметры без телескопических конструкторов
  • JDK: HttpRequest.newBuilder(), StringBuilder (неизменяемый String в конце)

А ещё Lombok @Builder; для record — компактный конструктор и withers

Подробно

Без билдера у неизменяемого объекта остаются два плохих варианта: сеттеры (и тогда он уже не immutable) или конструктор с восемью аргументами одного типа. Билдер Блоха решает обе проблемы: именованные шаги вместо позиционных аргументов и проверка всех инвариантов разом в build(). Примеры в JDK: HttpRequest.newBuilder() из Java 11, Stream.builder(), Locale.Builder.

Что хотят услышать

  • Проблема конструкторов и сеттеров.
  • Валидация в build.

Частые ошибки

  • Считать StringBuilder примером этого паттерна — это изменяемый буфер, совпало только название.
  • Путать Builder Блоха (борьба с телескопическими конструкторами) с Builder GoF (Director и разные представления).
