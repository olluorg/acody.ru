Чем вызов start() у потока отличается от прямого вызова run()?

JuniorМногопоточность
Ещё спрашивают так:
  • Как создать поток в Java?
  • Можно ли вызвать start() у потока дважды?
Коротко

start() создаёт новый поток, и уже он вызывает run(); прямой run() выполняется в текущем потоке, как обычный метод.

  • Повторный start() → IllegalThreadStateException: поток одноразовый
  • Способы: Thread с Runnable, ExecutorService, виртуальные потоки

А ещё В современном коде потоки руками почти не создают — задачи отдают в пул

Подробно

Thread.start() просит JVM создать новый поток выполнения; в нём будет вызван метод run(). Сам start() сразу возвращает управление, и теперь код работает параллельно.

Если вызвать run() напрямую, никакого нового потока не появится: метод выполнится в текущем потоке, как любой другой. Это классическая ошибка — код выглядит многопоточным, но работает последовательно, и заметно это только по производительности или по имени потока в логах.

Объект Thread одноразовый: повторный start() бросит IllegalThreadStateException, даже если поток уже завершился.

Способы запустить задачу:

  • new Thread(runnable).start() — вручную, для учебных примеров;
  • ExecutorService — пул потоков, основной вариант в приложениях;
  • Thread.ofVirtual().start(...) или Executors.newVirtualThreadPerTaskExecutor() — виртуальные потоки (Java 21).

Наследоваться от Thread обычно не стоит — лучше передавать Runnable или Callable.

Пример

Runnable task = () -> System.out.println(Thread.currentThread().getName());
task.run();                 // main
new Thread(task).start();   // Thread-0

Что хотят услышать

  • start() создаёт поток, run() — обычный вызов.
  • Одноразовость объекта Thread.
  • Современные способы: пулы и виртуальные потоки.

Частые ошибки

  • Вызывать run() напрямую и считать, что работа идёт параллельно.
  • Пытаться повторно запустить завершившийся поток.
