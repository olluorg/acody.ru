Какой порядок catch-блоков корректен для FileNotFoundException и IOException?

JuniorИсключения и ресурсы
Коротко

Сначала FileNotFoundException, затем IOException: catch проверяются сверху вниз, и общий тип перед частным делает частный недостижимым — ошибка компиляции.

  • FileNotFoundException наследует IOException
  • Multi-catch: catch (IOException | SQLException e), типы не должны быть родственными
  • Ловить частный тип стоит, только если реакция отличается

А ещё Порядок в multi-catch неважен

Подробно

catch проверяются сверху вниз. Если поставить IOException первым, catch для FileNotFoundException станет недостижимым, потому что FileNotFoundException наследуется от IOException.

Что хотят услышать

  • Правильный порядок и почему.

Частые ошибки

  • Ставить общий тип исключения раньше частного.
  • Думать, что выполнятся оба catch-блока.

Показать варианты и ответ

  • ✓Сначала FileNotFoundException, затем IOException
  • ✗Оба исключения нельзя ловить в одном try
