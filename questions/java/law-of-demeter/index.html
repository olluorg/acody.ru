Какой из фрагментов нарушает закон Деметры?

MiddleПринципы проектирования
Коротко

Нарушение — путешествие по графу чужих объектов: order.getCustomer().getAddress().getCity().getName() фиксирует в вызывающем коде всю структуру, и любое изменение по пути его ломает. Число точек само по себе не критерий.

  • Можно обращаться к своим полям, параметрам и созданным объектам
  • Лечение — «Tell, don't ask»: order.deliveryCity()
  • Fluent API и стримы закон не нарушают — каждый вызов возвращает тот же уровень абстракции

А ещё DTO и записи данных — тоже не нарушение: структура и есть их контракт

Подробно

Закон Деметры разрешает обращаться к полям своего объекта, своим параметрам и созданным объектам, но не к структуре чужих. Цепочка getCustomer().getAddress().getCity() фиксирует в вызывающем коде весь граф: любое изменение по пути его ломает. Лечение — «Tell, don't ask»: order.deliveryCity(). Fluent-цепочки и стримы нарушением не являются — каждый вызов возвращает тот же объект или ту же абстракцию.

Что хотят услышать

  • Суть закона.
  • Различие с fluent-цепочками.

Частые ошибки

  • Объявлять нарушением любую цепочку вызовов, включая билдеры и стримы.
  • Заменять цепочку геттеров на такую же цепочку внутри другого класса, не перенося поведение.
