Чем интерфейс AutoCloseable отличается от Closeable?

MiddleИсключения и ресурсы
Коротко

AutoCloseable (Java 7) — для любых ресурсов, close() бросает Exception. Closeable (java.io, старше) — его наследник под ввод-вывод: close() бросает IOException и обязан быть идемпотентным (повторный вызов ничего не делает).

  • AutoCloseable идемпотентность лишь рекомендует
  • Свой ресурс — объявить close() без throws или с узким исключением
  • Lock, соединения, сессии — AutoCloseable

А ещё Обёртка над lock в AutoCloseable позволяет использовать try-with-resources

Подробно

AutoCloseable добавили в Java 7 вместе с try-with-resources, и он намеренно объявляет close() бросающим Exception, чтобы подойти любому ресурсу — соединению с базой, блокировке, сессии. Closeable существовал раньше, живёт в java.io и сужает исключение до IOException. Важное практическое различие в контракте: повторный close() у Closeable обязан быть безвредным, тогда как AutoCloseable этого не требует, хотя реализовывать идемпотентность настоятельно рекомендуется. При проектировании собственного ресурса берут AutoCloseable и по возможности сужают объявленное исключение — это упрощает жизнь вызывающему коду.

Частые ошибки

  • Объявлять close() бросающим Exception в своём классе, заставляя всех ловить лишнее.
  • Считать, что try-with-resources работает только с java.io.
