Чем String, StringBuilder и StringBuffer отличаются?

JuniorОсновы языка
Коротко

String неизменяем: каждая «правка» — новый объект. StringBuilder — изменяемый буфер, быстрый, не потокобезопасный. StringBuffer — то же, но с synchronized на каждом методе — устаревший вариант.

  • Конкатенация в цикле — StringBuilder, иначе квадратичная работа
  • Одно выражение a + b + c компилятор оптимизирует сам
  • StringBuffer почти не нужен: буфер редко делят между потоками

А ещё Известный размер — new StringBuilder(capacity)

Подробно

String s = "";
for (int i = 0; i < n; i++) s += i;        // n новых строк, O(n²)

StringBuilder sb = new StringBuilder();
for (int i = 0; i < n; i++) sb.append(i);  // один растущий буфер
String result = sb.toString();

StringBuilder хранит массив и растёт удвоением, как ArrayList. Методы возвращают this — цепочки append(a).append(b). Есть insert, reverse, deleteCharAt.

StringBuffer появился в Java 1.0, StringBuilder — в Java 5 как его несинхронизированная замена. Синхронизация на каждом append почти никогда не нужна: строку собирают в одном потоке.

Компилятор превращает "a" + x + "b" в эффективную конкатенацию (Java 9+: StringConcatFactory), поэтому вне циклов + нормален и читается лучше. Для соединения коллекции — String.join или Collectors.joining.

Что хотят услышать

  • Изменяемость и потокобезопасность каждого.
  • Почему конкатенация в цикле плоха.

Частые ошибки

  • Собирать большие строки в цикле через +=.
  • Думать, что StringBuilder потокобезопасен.

Показать варианты и ответ

  • ✓String неизменяем; StringBuilder изменяем; StringBuffer — то же, но синхронизирован
  • ✗String изменяем через concat; StringBuffer быстрее StringBuilder в одном потоке
  • ✗Все три неизменяемы
