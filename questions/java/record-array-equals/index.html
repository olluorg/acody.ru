Что произойдёт, если объявить record с полем-массивом и сравнить два таких объекта с одинаковым содержимым массива?

MiddleСовременная JavaJava >=16
Коротко

equals вернёт false: сгенерированный equals сравнивает компоненты их собственным equals, а у массива это сравнение по ссылке. hashCode тоже будет по идентичности, toString напечатает адрес.

  • Решение: хранить List (List.copyOf) вместо массива
  • Или переопределить equals, hashCode, toString через Arrays.equals, Arrays.hashCode
  • Массив ещё и изменяем — нужна копия

А ещё IDE и анализаторы предупреждают о массиве в record

Подробно

Это неочевидная ловушка: record выглядит так, будто «всё сделает правильно», но для ссылочных компонентов он вызывает их собственный equals, а у массива это сравнение по идентичности. Заодно и hashCode окажется бесполезным, и toString напечатает адрес вместо содержимого. Правильные решения: хранить неизменяемый List вместо массива — тогда всё работает ожидаемо — либо вручную переопределить equals, hashCode и toString с использованием Arrays. Тот же принцип касается любого компонента с неудачным equals.

Частые ошибки

  • Считать, что record корректно сравнит любые компоненты.
  • Хранить в record изменяемый массив и полагаться на неизменяемость.
