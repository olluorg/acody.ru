Чем HashMap отличается от Hashtable и ConcurrentHashMap?

MiddleКоллекции
Ещё спрашивают так:
  • Можно ли использовать HashMap из нескольких потоков?
Коротко

HashMap — не потокобезопасна, допускает один null-ключ и null-значения. Hashtable — устаревшая, все методы synchronized, null запрещён. ConcurrentHashMap — потокобезопасная с мелкой блокировкой, null запрещён.

  • Однопоточно или под внешней синхронизацией — HashMap
  • Конкурентный доступ — ConcurrentHashMap
  • Hashtable в новом коде не нужна

HashMap из нескольких потоков: одновременные put теряют записи, а при расширении таблицы данные могут оказаться в неверных корзинах (до Java 8 — даже бесконечный цикл в цепочке). Безопасно только чтение карты, которая больше не меняется и была безопасно опубликована.

Hashtable — класс из Java 1.0: synchronized на каждом методе, итерация через Enumeration, null запрещены. Медленнее ConcurrentHashMap под конкуренцией и не даёт атомарных составных операций.

ConcurrentHashMap — выбор для общего кэша, счётчиков (merge(key, 1, Integer::sum)), реестров. Итератор не бросает ConcurrentModificationException и может видеть часть параллельных изменений.
