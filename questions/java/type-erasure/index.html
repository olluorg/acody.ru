Что означает стирание типов (type erasure)?

JuniorДженерики
Ещё спрашивают так:
  • Почему нельзя написать new T()?
  • Почему List<String> и List<Integer> — один класс в рантайме?
  • Что такое type erasure в дженериках?
Коротко

Стирание типов: компилятор проверяет типы, но в байткоде параметр заменяется границей (обычно Object) — в рантайме его нет.

  • Сделано ради совместимости со старым кодом без дженериков
  • Нельзя: new T(), new T[], instanceof List<String>, обобщённое исключение

А ещё List<String> и List<Integer> в рантайме — один класс ArrayList

Подробно

Дженерики появились в Java 5, и разработчики языка сохранили совместимость с уже написанным кодом: старые и новые классы должны были работать вместе. Поэтому параметры типов существуют только на этапе компиляции. Компилятор проверяет типы и вставляет нужные приведения, а в байткоде T заменяется на свою верхнюю границу — Object или, например, Comparable для <T extends Comparable<T>>.

Практические последствия:

  • нельзя создать объект или массив по параметру: new T(), new T[10] — тип неизвестен в рантайме;
  • нельзя проверить obj instanceof List<String> — только List<?>;
  • List<String> и List<Integer> во время выполнения — один и тот же класс;
  • нельзя перегрузить методы, отличающиеся только параметром (void f(List<String>) и void f(List<Integer>));
  • нельзя объявить обобщённый класс исключения.

Обходной путь — передавать Class<T> явно (clazz.getDeclaredConstructor() .newInstance()) или токен типа, как делают JSON-библиотеки.

Пример

List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass()); // true

<T> T create(Class<T> type) throws Exception {
    return type.getDeclaredConstructor().newInstance();
}
