Чем switch-выражение (case L -> …) надёжнее старого switch?

MiddleСовременная JavaJava >=14
Коротко

Стрелочный case L -> не проваливается и не требует break; switch-выражение возвращает значение (для блока — yield); по enum и sealed-типам компилятор проверяет полноту — забытый вариант даёт ошибку компиляции.

  • Несколько меток: case SAT, SUN -> "выходной"
  • Java 21: pattern matching в case и guard-условия when
  • case null — явная обработка null вместо NPE

А ещё Старый switch с двоеточием тоже доступен, но без проверки полноты в statement-форме

Подробно

case L -> … не проваливается и не требует break, а всё выражение возвращает значение (для блока — через yield). Главный выигрыш — исчерпываемость: switch по enum или sealed-типу обязан покрыть все варианты, и компилятор это проверяет. Это надёжнее старого statement-switch с легко забываемым break.

Пример

String kind = switch (day) {
    case SAT, SUN -> "выходной";
    case MON, TUE, WED, THU, FRI -> {
        log(day);
        yield "рабочий";
    }
};

Что хотят услышать

  • Отсутствие fall-through.
  • Значение и yield.
  • Исчерпываемость.

Частые ошибки

  • Ждать fall-through в стрелочном case.
  • Забывать yield в блочной ветви.
