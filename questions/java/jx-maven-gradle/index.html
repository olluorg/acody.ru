Зачем нужны Maven и Gradle и как устроена сборка Java-проекта?

JuniorТестирование и логирование
Ещё спрашивают так:
  • Чем Maven отличается от Gradle?
  • Что такое pom.xml?
Коротко

Система сборки скачивает зависимости нужных версий из репозитория (Maven Central), компилирует код, запускает тесты и упаковывает результат (jar). Maven описывает проект декларативно в pom.xml с фиксированным жизненным циклом (compile → test → package → install). Gradle — скрипт на Kotlin или Groovy (build.gradle.kts), гибче и обычно быстрее за счёт инкрементальной сборки и кэша.

  • Зависимость задаётся координатами groupId:artifactId:version
  • Область (scope) test — зависимость только для тестов
  • Wrapper (mvnw, gradlew) фиксирует версию инструмента для всех разработчиков

А ещё Конфликт версий транзитивных зависимостей смотрят через mvn dependency:tree или gradle dependencies

Подробно

Maven:

<dependency>
  <groupId>org.postgresql</groupId>
  <artifactId>postgresql</artifactId>
  <version>42.7.4</version>
</dependency>

./mvnw package — скомпилировать, прогнать тесты, собрать jar.

Gradle:

dependencies {
    implementation("org.postgresql:postgresql:42.7.4")
    testImplementation("org.junit.jupiter:junit-jupiter:5.11.0")
}

./gradlew build — то же самое.

Что хотят услышать

  • Зачем система сборки: зависимости, компиляция, тесты, упаковка.
  • pom.xml и жизненный цикл Maven.
  • Gradle-скрипт и его плюсы.
  • Wrapper и дерево зависимостей.
