Чем опасно использование raw type, например List вместо List<String>?

MiddleДженерики
Коротко

Raw type выключает проверку дженериков для всего выражения: в список строк можно положить число, а ClassCastException появится далеко — при чтении, где компилятор вставил приведение.

  • Компилятор лишь предупреждает: unchecked
  • Существуют только для совместимости со старым кодом
  • Вместо raw — List<?> (безопасно читать) или List<Object>

А ещё Raw-ссылка стирает дженерики даже в несвязанных методах класса

Подробно

Особенно коварно то, что отключается не только проверка конкретного параметра: при работе через raw-ссылку компилятор перестаёт применять дженерик-правила ко всему объявлению, включая параметры, к которым претензий не было. Ошибка проявится потом — при чтении из коллекции, где вставленное приведение бросит ClassCastException, и стектрейс укажет на место чтения, а не на место неправильной записи. Raw types существуют исключительно ради совместимости с кодом, написанным до Java 5, и в новом коде им места нет. Если параметр действительно неважен, правильная форма — безграничный wildcard List<?>: он сохраняет проверки типов, запрещая небезопасное добавление.

Частые ошибки

  • Путать List и List<?> — второе типобезопасно.
