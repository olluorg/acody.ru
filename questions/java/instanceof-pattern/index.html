Что даёт pattern matching в instanceof по сравнению с классической проверкой?

MiddleСовременная JavaJava >=16
Коротко

Проверка и приведение объединяются: if (o instanceof String s) сразу даёт переменную s нужного типа. Нет дублирующего приведения, которое может разойтись с проверкой.

  • Область видимости — по потоку управления: после if (!(o instanceof String s)) return; переменная доступна дальше
  • Можно в условиях: o instanceof String s && !s.isEmpty()
  • Удобно в equals: o instanceof Point p && x == p.x

А ещё Java 21: record-паттерны — o instanceof Point(int x, int y)

Подробно

Устраняется классическая триада «проверил — привёл — присвоил», в которой приведение дублирует уже сделанную проверку и может разъехаться с ней при правках. Изящная деталь — область видимости определяется потоком выполнения: после if (!(o instanceof String s)) return; переменная s доступна в остальной части метода, потому что компилятор знает, что иначе туда не дойти. Семантика null не изменилась: instanceof по-прежнему даёт false для null, поэтому отдельная проверка на null не нужна. Дальнейшее развитие идеи — деконструкция record прямо в шаблоне.

Что хотят услышать

  • Что объединяется.
  • Область видимости переменной.

Частые ошибки

  • Добавлять лишнюю проверку на null перед instanceof.
  • Считать, что переменная шаблона доступна всегда, независимо от условия.
