Функция значения в Collectors.toMap вернула null для одного из элементов. Что произойдёт?

MiddleЛямбды и Stream API
Коротко

NullPointerException, хотя HashMap null-значения допускает: коллектор использует merge, а он по контракту запрещает null — не отличить от отсутствия ключа.

  • Проявляется только на конкретных данных — часто уже в проде
  • Обход: отфильтровать null, подставить значение по умолчанию, собрать вручную через collect(HashMap::new, (m, e) -> m.put(...), Map::putAll)
  • Или хранить Optional — но это спорно

А ещё null-ключ toMap допускает

Подробно

Причина в реализации: коллектор использует merge, а этот метод по контракту запрещает null-значение, потому что не может отличить его от отсутствия ключа. Ловушка неприятна тем, что проявляется на конкретных данных и часто уже в production. Обходные пути: отфильтровать такие элементы заранее, подставить значение по умолчанию, либо собирать через Collectors.groupingBy или через toMap с явной фабрикой карты и собственной логикой. Стоит помнить и вторую ловушку того же коллектора: при повторяющемся ключе без функции слияния бросается IllegalStateException — и это отдельная от null-значений проблема.

  • Путать поведение при дублирующемся ключе и при null-значении.
