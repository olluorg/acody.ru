В каком порядке выполняется инициализация при создании объекта подкласса?

MiddleОсновы языка
Ещё спрашивают так:
  • В каком порядке инициализируются статические члены, поля и конструкторы при создании наследника?
  • В каком порядке инициализируются статические члены, поля объекта и конструкторы при создании экземпляра класса-наследника?
Коротко

Один раз при инициализации класса: static-поля и static-блоки — родитель, затем наследник. На каждый new: конструктор наследника сразу вызывает super(), отрабатывают поля и блоки родителя, тело его конструктора, затем поля и блоки наследника и тело его конструктора.

  • Поля и блоки — в порядке объявления
  • Ловушка: переопределённый метод, вызванный из конструктора родителя, видит поля наследника пустыми (null, 0)
  • Из конструктора не вызывают переопределяемые методы

А ещё Класс инициализируется лениво — при первом активном использовании

Подробно

Отсюда вытекает известная ловушка: если конструктор суперкласса вызывает метод, переопределённый в подклассе, тот выполнится до инициализации полей подкласса и увидит их значениями по умолчанию — null и нули. Именно поэтому из конструктора не вызывают переопределяемые методы. Вторая практическая деталь: статические блоки выполняются один раз при инициализации класса, а она происходит лениво — при первом создании объекта, обращении к статическому члену, не являющемуся константой времени компиляции, или обращении к статическому методу. Инициализаторы полей и блоки внутри одного класса выполняются в порядке их появления в тексте.

Что хотят услышать

  • Порядок статической и экземплярной инициализации.
  • Ловушка с вызовом переопределённого метода.

Частые ошибки

  • Вызывать переопределяемый метод из конструктора.
  • Считать, что статический блок отработает в момент загрузки класса — он отработает при инициализации.
