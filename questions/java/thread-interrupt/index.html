Что верно про прерывание потока через interrupt()?

MiddleМногопоточность
Ещё спрашивают так:
  • Как корректно остановить фоновый поток и почему нельзя вызвать Thread.stop?
  • Фоновая задача в потоке должна корректно останавливаться при выключении приложения. Как это сделать и почему нельзя просто вызвать Thread.stop?
Коротко

interrupt() — просьба, а не приказ: выставляет флаг; блокирующие sleep, wait, join бросают InterruptedException и сбрасывают флаг. Поток проверяет флаг сам и завершается в безопасной точке. Thread.stop убран, потому что бросал исключение в случайном месте и оставлял данные испорченными.

  • Поймал InterruptedException и не пробросил — восстанови флаг: Thread.currentThread().interrupt()
  • Пустой catch превращает отмену в тишину
  • Пулы: shutdown, shutdownNow (прерывает потоки), awaitTermination

А ещё Альтернатива для простого цикла — volatile boolean

Подробно

Почему нет принудительной остановки. Thread.stop бросал ThreadDeath в произвольной точке — например, посреди изменения структуры данных. Мониторы освобождались, а инварианты оставались нарушенными. Метод был устаревшим с Java 1.2, а в Java 20+ бросает UnsupportedOperationException.

Кооперативная отмена:

while (!Thread.currentThread().isInterrupted()) {
    try {
        process(queue.take());
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();   // восстановить флаг
        break;
    }
}
  • работающий поток сам проверяет isInterrupted();
  • заблокированный в sleep, wait, join, BlockingQueue.take получает InterruptedException, при этом флаг сбрасывается;
  • поймав исключение, нужно завершиться или пробросить его, а если нельзя — восстановить флаг для вызывающего кода.

Блокирующий ввод-вывод на старых потоках прерывание не замечает — помогает закрытие ресурса или каналы NIO (InterruptibleChannel).

Остановка пула: shutdown() — не принимать новые задачи, дождаться текущих; shutdownNow() — прервать работающие; затем awaitTermination с таймаутом.

Что хотят услышать

  • Кооперативная модель прерывания.
  • Сброс флага при исключении и его восстановление.
  • Почему Thread.stop опасен.
  • Остановка пула.

Частые ошибки

  • Пустой catch InterruptedException.
  • Ожидать, что interrupt мгновенно остановит поток.
