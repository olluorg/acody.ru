Что верно про иерархию Collections Framework?

JuniorКоллекции
Коротко

Iterable → Collection → List, Set, Queue; Map — отдельная ветвь, не Collection: она хранит пары, а не элементы.

  • List — порядок и индексы, Set — уникальность, Queue и Deque — порядок обработки
  • Map связана с коллекциями через keySet, values, entrySet
  • SequencedCollection и SequencedMap (Java 21) — общий порядок: getFirst, getLast, reversed

А ещё Iterable делает возможным for-each

Подробно

Map не является Collection, потому что оперирует парами ключ-значение, а не отдельными элементами: у Collection сигнатура add(E), которая для карты бессмысленна. Связь всё же есть — через представления keySet(), values() и entrySet(), каждое из которых уже является коллекцией и отражает изменения исходной карты. Iterable с единственным методом iterator() лежит выше Collection и обеспечивает работу for-each — реализовать его может и ваш собственный класс.

Что хотят услышать

  • Ветви иерархии и почему Map отдельно.
  • Назначение List, Set, Queue.

Частые ошибки

  • Считать Map частью Collection.
  • Забывать, что keySet и entrySet — это представления, а не копии.
