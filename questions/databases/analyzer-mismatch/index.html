Документы проиндексированы, но поиск по очевидно присутствующему слову ничего не находит. Какая причина наиболее вероятна?

MiddleПолнотекстовый поискElasticsearch
Ещё спрашивают так:
  • Почему Elasticsearch не находит слово, которое есть в документе?
Коротко

Совпадать должны термины, а не исходные строки: если текст при индексации и запрос при поиске проходят разные анализаторы, термины не совпадут.

  • Поле keyword хранит строку целиком — частичный поиск не сработает
  • Морфология: «кошками» и «кошка» совпадут только со стеммингом для русского
  • Запрос term не анализируется, match — анализируется

А ещё Проверка: _analyze API показывает, какие термины получаются

Подробно

Анализатор превращает текст в термины: разбивает на токены, приводит к нижнему регистру, отбрасывает стоп-слова, приводит слова к основе. Если поле проиндексировано с одним анализатором, а запрос разбирается другим, слово «Иванову» может стать термином «иванов» в индексе и остаться «Иванову» в запросе — совпадения нет. Вторая частая причина того же рода: поле объявлено как точное значение без анализа, и тогда поиск работает только по полному совпадению строки целиком. Отладка стандартная — прогнать текст и запрос через API анализа и сравнить получившиеся термины; помнить при этом, что смена анализатора требует переиндексации.

Что хотят услышать

  • Термины против строк.
  • Типичные причины: keyword, разные анализаторы, term против match.
  • Как диагностировать.

Частые ошибки

  • Менять анализатор и ожидать эффекта без переиндексации.
  • Путать анализируемое текстовое поле и поле для точного совпадения.
