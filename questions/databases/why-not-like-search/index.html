Почему полнотекстовый поиск не делают запросом LIKE '%слово%'?

JuniorПолнотекстовый поискSQL
Ещё спрашивают так:
  • Почему LIKE плох для поиска?
Коротко

LIKE '%слово%' не использует обычный индекс (ведущий шаблон) — читает всю таблицу, и качество поиска примитивное: нет морфологии, опечаток, ранжирования.

  • В PostgreSQL: полнотекстовый поиск (tsvector, GIN) или pg_trgm для подстрок
  • Для серьёзного поиска — Elasticsearch / OpenSearch
  • LIKE 'слово%' (префикс) может использовать B-дерево

А ещё «кошками» не найдёт «кошка» без морфологии

Подробно

Проблем две, и обе существенные. Производительность: стоимость растёт линейно с объёмом текста, потому что база вынуждена просмотреть каждую строку. Качество: пользователь ищет «купить телефон», а в тексте «телефоны купили» — точного вхождения нет, и поиск ничего не найдёт; ранжирования результатов тоже не будет. Поисковые системы решают обе задачи, заранее разбирая текст на термины и строя по ним индекс.

Что хотят услышать

  • Почему индекс не работает.
  • Недостатки качества поиска.
  • Альтернативы.

Частые ошибки

  • Оставлять поиск на LIKE до момента, когда объём данных вырастет.
  • Ожидать от такого поиска релевантной сортировки результатов.
