Как написать простой HTTP API на FastAPI?

JuniorВеб-фреймворки
Ещё спрашивают так:
  • Как объявить эндпоинт в FastAPI?
  • Чем path-параметр отличается от query-параметра?
Коротко

Создать приложение app = FastAPI(), объявить обработчики декораторами @app.get, @app.post и др. Параметр из пути (/items/{item_id}) становится аргументом функции, остальные простые аргументы — query-параметрами, а аргумент-модель Pydantic — телом запроса. Типы аргументов проверяются автоматически, ошибка — 422. Документация API доступна по /docs. Запуск — ASGI-сервером uvicorn.

  • Код ответа: status_code в декораторе, ошибки — HTTPException
  • response_model задаёт схему ответа и скрывает лишние поля
  • async def — если внутри асинхронные вызовы; синхронную функцию FastAPI выполнит в пуле потоков

А ещё Документация /docs строится из аннотаций — отдельно писать её не нужно

Подробно

Пример:

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI()

class ItemIn(BaseModel):
    name: str
    price: float

@app.get("/items/{item_id}")
def get_item(item_id: int, details: bool = False):
    item = db.get(item_id)
    if item is None:
        raise HTTPException(status_code=404, detail="Нет такого товара")
    return item

@app.post("/items", status_code=201)
def create_item(item: ItemIn):
    return db.add(item)
uvicorn main:app --reload

Что хотят услышать

  • Декораторы маршрутов.
  • Path, query, тело через Pydantic.
  • Автоматическая проверка и 422.
  • HTTPException, uvicorn, /docs.

  • ✗Параметры пути и query — аргументы функции, а тело запроса читают вручную из строки, без Pydantic
  • ✗FastAPI-приложение запускают через python main.py без сервера
  • ✓Параметры пути и query — аргументы функции, модель Pydantic — тело; неверные типы дают 422
  • ✗Документацию API нужно писать отдельно вручную
