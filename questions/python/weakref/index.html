Что такое слабые ссылки (weakref) и где они нужны?

MiddleВнутреннее устройство
Ещё спрашивают так:
  • Как сделать кэш, который не мешает удалению объектов?
Коротко

Слабая ссылка не увеличивает счётчик ссылок: объект удаляется, когда исчезнут обычные ссылки, а слабая начинает возвращать None. Применение: кэши и реестры, которые не продлевают жизнь объектов (WeakValueDictionary, WeakKeyDictionary), разрыв циклов «родитель ↔ ребёнок», колбэки, наблюдатели.

  • weakref.ref(obj)() — получить объект или None
  • weakref.finalize — надёжная замена __del__ для очистки
  • Не у всех типов есть слабые ссылки: int, str, tuple, list без подкласса — нет

А ещё Класс с __slots__ должен включить '__weakref__', чтобы поддерживать их

Подробно

Зачем. Обычный словарь-кэш держит объекты вечно: даже если программа больше не использует изображение, кэш не даст его освободить. WeakValueDictionary хранит значения слабо — запись пропадает, когда объект больше никому не нужен.

Циклы. Дерево, где дети ссылаются на родителя, создаёт циклы и работу для сборщика. Ссылка ребёнка на родителя через weakref.ref цикл разрывает.

Наблюдатели. Издатель, хранящий подписчиков сильными ссылками, не даёт им умереть — классическая утечка. weakref.WeakSet или WeakMethod для связанных методов решают это.

finalize. weakref.finalize(obj, cleanup, path) вызовет cleanup при удалении объекта или при выходе из интерпретатора — надёжнее __del__.

Пример

import weakref

class Image: ...
cache = weakref.WeakValueDictionary()

img = Image()
cache["logo"] = img
del img                 # последняя сильная ссылка
print(cache.get("logo"))  # None — запись исчезла сама
