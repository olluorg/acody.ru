Как найти, что тормозит в Python-программе?

MiddleСложность и производительность
Ещё спрашивают так:
  • Чем профилировать Python в продакшене?
Коротко

Сначала измерить, потом оптимизировать. cProfile (+ snakeviz) — время по функциям локально. py-spy — сэмплирующий профилировщик, подключается к работающему процессу без перезапуска и почти без накладных расходов, строит flame graph. line_profiler — построчно. Память — tracemalloc, memray.

  • timeit — для микроизмерений одного выражения
  • Профиль под реалистичной нагрузкой: узкое место часто — ввод-вывод, а не CPU
  • py-spy dump — стеки всех потоков зависшего процесса

А ещё Scalene разделяет время Python-кода, нативного кода и памяти

Подробно

Порядок работы:

  1. Воспроизвести медленный сценарий и измерить время целиком.
  2. Профиль: python -m cProfile -o out.prof app.py, затем snakeviz out.prof — какие функции занимают больше всего суммарного (cumtime) и собственного (tottime) времени.
  3. В проде — py-spy top --pid 1234 или py-spy record -o flame.svg --pid 1234: сэмплирует стек снаружи процесса, код не меняется.
  4. Найденную горячую функцию — line_profiler построчно.

Типичные находки: запросы к БД в цикле (N+1), лишние сериализации JSON, квадратичные алгоритмы (x in list в цикле), построение строк конкатенацией, регулярные выражения, компилируемые в цикле.

Память: tracemalloc.start() и сравнение снимков показывают, где выделяется память; memray строит flame graph по аллокациям.

cProfile сам замедляет код в разы и искажает картину для мелких функций — сэмплирующие профилировщики точнее для сравнения.

Что хотят услышать

  • Измерение перед оптимизацией.
  • cProfile и py-spy, в чём разница.
  • Типичные причины медленного кода.
