Чем буферизованный канал отличается от небуферизованного и что происходит при закрытии канала?

JuniorГорутины и каналы
Ещё спрашивают так:
  • Как работают каналы в Go?
  • Кто должен закрывать канал?
Коротко

Небуферизованный канал — отправка блокируется, пока получатель не заберёт значение: синхронная встреча. Буферизованный (make(chan T, n)) — отправка блокируется только при полном буфере. close сообщает «значений больше не будет»: получение из закрытого канала сразу возвращает нулевое значение и ok == false, отправка в закрытый — panic.

  • Закрывает отправитель, а не получатель
  • for v := range ch — читает до закрытия
  • Операции с nil-каналом блокируются навсегда

А ещё «Не общайтесь через общую память — делитесь памятью через общение»

Небуферизованный канал синхронизирует две горутины: после передачи обе знают, что значение доставлено. Буфер сглаживает всплески и развязывает производителя и потребителя, но не должен маскировать медленного потребителя.

Кто закрывает: единственный отправитель, когда данных больше нет. При нескольких отправителях — отдельная координация (WaitGroup и закрытие после завершения всех).

Направленные типы: chan<- T — только отправка, <-chan T — только получение; ограничивают использование в сигнатурах.

Пример

jobs := make(chan int, 100)
results := make(chan int)

for w := 0; w < 4; w++ {
    go func() {
        for j := range jobs {          // до close(jobs)
            results <- j * j
        }
    }()
}
for i := 0; i < 10; i++ { jobs <- i }
close(jobs)
