Что такое горутина и чем она отличается от потока ОС?

JuniorГорутины и каналы
Ещё спрашивают так:
  • Как устроен планировщик Go (модель GMP)?
  • Сколько горутин можно запустить?
Коротко

Горутина — лёгкий поток, управляемый рантаймом Go: стартовый стек ~2 КБ (растёт по необходимости), создание и переключение в разы дешевле потока ОС — можно держать сотни тысяч. Планировщик M:N распределяет горутины (G) по потокам ОС (M) через логические процессоры (P), число которых = GOMAXPROCS (по умолчанию — число ядер).

  • Блокирующий системный вызов — планировщик отдаёт P другому потоку
  • Сетевой ввод-вывод — через netpoller (epoll): горутина паркуется, поток свободен
  • Вытесняющий планировщик (с Go 1.14) — долгий цикл не захватит ядро навсегда

А ещё main завершилась — программа завершается, не дожидаясь горутин

Подробно

Запуск: go f(x) — функция выполняется конкурентно; аргументы вычисляются сразу. Результат горутина возвращает через канал или общую структуру под мьютексом.

Модель GMP:

  • G — горутина: стек, указатель команды, состояние;
  • M — поток ОС;
  • P — логический процессор с локальной очередью горутин; поток выполняет код Go, только держа P.

Свободный P крадёт горутины из чужих очередей (work stealing). При блокирующем системном вызове M отпускает P, и тот уходит к другому потоку. Сеть обслуживает netpoller: горутина «спит», не занимая поток, а когда сокет готов, её снова ставят в очередь.

Сравнение с потоками ОС: поток — мегабайты стека и переключение через ядро; горутина — килобайты и переключение в пространстве пользователя. Поэтому в Go принят стиль «горутина на запрос» с простым блокирующим кодом — то же, к чему Java пришла с виртуальными потоками.

Ожидание завершения — sync.WaitGroup или каналы; без этого main выйдет раньше.
