Какими командами вы диагностируете проблему на Linux-сервере?

MiddleLinux и диагностика
Ещё спрашивают так:
  • Сервис не отвечает — что смотреть на сервере?
Коротко

Порядок: жив ли процесс (systemctl status, ps) → логи (journalctl, файлы приложения) → ресурсы (top, free, df, iostat) → сеть (ss -tlnp — слушает ли порт, curl localhost, dig) → что изменилось (деплой, конфиг, сертификат). Первые 60 секунд: uptime, dmesg | tail, vmstat 1, mpstat, pidstat, iostat -xz 1, free -m, sar -n DEV 1, top.

  • ss заменил netstat; ip заменил ifconfig
  • strace -p PID — что процесс делает прямо сейчас (системные вызовы)
  • Сначала посмотреть, потом перезапускать — иначе улики пропадут

А ещё Снять дамп потоков и состояние до перезапуска — для разбора причин

Подробно

Проверочный список:

uptime                    # load average
dmesg -T | tail           # ошибки ядра, OOM
systemctl status app      # состояние и последний лог
journalctl -u app -n 100  # подробнее
ss -tlnp                  # какие порты слушаются и каким процессом
curl -sv localhost:8080/health
df -h; free -h            # диск и память
top / htop                # кто ест CPU и память
iostat -xz 1              # диск
dig api.example.com       # DNS
openssl s_client -connect host:443   # TLS, срок сертификата

Типичные находки: закончилось место, лимит открытых файлов, истёк сертификат, упала зависимость (БД), DNS не резолвит, процесс слушает только 127.0.0.1, файрвол закрыл порт.

Культура: фиксировать в заметках инцидента, что проверено и что найдено; после устранения — разбор причин без поиска виноватых.

Что хотят услышать

  • Системный порядок проверки.
  • Конкретные команды и что они показывают.
  • Сохранить информацию до перезапуска.
