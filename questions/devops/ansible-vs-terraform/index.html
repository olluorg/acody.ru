Чем Ansible отличается от Terraform и когда что применять?

MiddleИнфраструктура как код и облакаTerraform
Ещё спрашивают так:
  • Что такое идемпотентность в управлении конфигурацией?
Коротко

Terraform — создание инфраструктуры (provisioning): декларативно, со state, хорош для облачных ресурсов — сетей, ВМ, баз, DNS. Ansible — настройка существующих машин (configuration management): по SSH без агента выполняет задачи плейбука — пакеты, файлы, сервисы, пользователи. Их часто сочетают: Terraform создаёт ВМ, Ansible их настраивает.

  • Идемпотентность: повторный запуск не меняет то, что уже в нужном состоянии
  • Модули Ansible идемпотентны, команды shell — нет: нужны creates или changed_when
  • Ansible не хранит state — удалённый из плейбука ресурс останется на сервере

А ещё С контейнерами и неизменяемыми образами роль Ansible смещается к сборке образов и обслуживанию хостов

Подробно

Сравнение:

TerraformAnsible
задачасоздать ресурсынастроить машины
стильдекларативныйпроцедурный с декларативными модулями
stateестьнет
доступAPI облакаSSH, без агента
удалениеубрали из кода — удалитнужно явно описать удаление

Пример задачи Ansible:

- name: nginx установлен и запущен
  hosts: web
  become: true
  tasks:
    - ansible.builtin.apt: { name: nginx, state: present }
    - ansible.builtin.template: { src: site.conf.j2, dest: /etc/nginx/conf.d/site.conf }
      notify: reload nginx
  handlers:
    - name: reload nginx
      ansible.builtin.service: { name: nginx, state: reloaded }

Другие инструменты: Packer — сборка образов ВМ, Pulumi — инфраструктура на обычных языках программирования, Helm — пакеты для Kubernetes.
