Как ограничивать сетевой доступ к серверам и сервисам?

JuniorСети и прокси
Ещё спрашивают так:
  • Чем stateful-файрвол отличается от stateless?
  • Что такое security group?
Коротко

Принцип — запрещено всё, что не разрешено явно. Слои защиты: файрвол хоста (nftables/iptables, ufw), облачные security groups у каждой машины, сетевые ACL подсетей, NetworkPolicy в Kubernetes. Наружу открыты только 80/443 балансировщика; БД, кэши и брокеры — только из подсети приложений; SSH — только с bastion или через VPN.

  • Stateful-файрвол помнит соединения: ответный трафик разрешён автоматически
  • Security group разрешает доступ по ссылке на другую группу, а не только по IP
  • Сервис, слушающий 0.0.0.0 без файрвола, доступен всем — частая причина утечек баз

А ещё Docker публикует порты в обход ufw, правя iptables напрямую

Подробно

Пример политики для веб-сервиса:

откудакудапорт
интернетбалансировщик443
балансировщикприложения8080
приложенияPostgreSQL5432
bastionвсе узлы22

Stateful и stateless. Security groups и nftables с conntrack — stateful: разрешили входящее — ответ пройдёт. Сетевые ACL облака — stateless: нужно явно разрешить и обратное направление (эфемерные порты).

Kubernetes NetworkPolicy: по умолчанию все поды видят друг друга. Политика «запретить всё входящее» на namespace и явные разрешения ограничивают последствия взлома одного сервиса. Работает, только если сетевой плагин поддерживает политики (Calico, Cilium).

Проверка: nmap снаружи — какие порты реально открыты.

Что хотят услышать

  • Принцип запрета по умолчанию и слои защиты.
  • Stateful против stateless.
  • Практическая схема доступа.
