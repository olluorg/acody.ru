Что такое Fiber и конкурентный рендеринг в React?

SeniorReact
Ещё спрашивают так:
  • Как React прерывает рендеринг?
Коротко

Fiber — внутренняя структура React: каждый элемент дерева представлен узлом-«волокном» с ссылками на родителя, потомка и соседа. Это позволяет выполнять работу кусками, приостанавливать её, отдавать управление браузеру и отбрасывать устаревшую. Рендер делится на фазу render (вычислить изменения, можно прервать) и фазу commit (применить к DOM синхронно, нельзя прервать). Конкурентный рендеринг использует это для приоритетов: срочные обновления (ввод) обгоняют несрочные (transition), Suspense показывает запасной интерфейс, пока данные не готовы.

  • Двойная буферизация: текущее дерево и дерево в работе
  • Побочные эффекты нельзя делать при рендере — он может выполниться несколько раз
  • StrictMode в разработке намеренно повторяет рендер, чтобы найти нечистый код

А ещё Конкурентность — не многопоточность: всё в одном потоке, но с прерываниями

Подробно

Последствия для кода: рендер должен быть чистым, подписки на внешние хранилища — через useSyncExternalStore (иначе возможен «разрыв» интерфейса), эффекты — после commit.

Что хотят услышать

  • Fiber как единица работы.
  • Фазы render и commit.
  • Приоритеты и прерывание.
  • Требование чистого рендера.
