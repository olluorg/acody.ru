Как избежать лишних перерисовок при использовании Context и почему Context — не менеджер состояния?

MiddleReact
Ещё спрашивают так:
  • Почему все компоненты перерисовываются при изменении контекста?
Коротко

Все потребители контекста перерисовываются, когда value меняется по ссылке. Частая ошибка — объект в value создаётся заново на каждом рендере провайдера: value={{user, setUser}} — тогда перерисовываются все даже без изменений. Лечение: мемоизировать value (useMemo), разделять контексты (данные и функции отдельно, часто и редко меняющееся отдельно), опускать провайдер ниже. Context лишь доставляет значение — у него нет селекторов, подписки на часть, middleware; для сложного часто меняющегося состояния берут Zustand, Redux, Jotai.

  • Компонент не может подписаться на часть контекста
  • Функции из useState стабильны — их удобно класть в отдельный контекст
  • React.memo не спасает от перерисовки потребителя контекста

А ещё Проверяйте Profiler'ом, прежде чем оптимизировать

Подробно

const value = useMemo(() => ({ user, login, logout }), [user]);
return <AuthCtx.Provider value={value}>{children}</AuthCtx.Provider>;

Что хотят услышать

  • Перерисовка при смене ссылки value.
  • useMemo и разделение контекстов.
  • Отсутствие селекторов — почему не менеджер состояния.

Проверьте себя

Один верный вариант. Подумайте, потом откройте ответ.

Показать варианты и ответ
  • ✗Потребители перерисовываются только если изменилось поле, которое они используют
  • ✓Мемоизировать value, разделять контексты по частоте изменений; Context лишь доставляет значение и не умеет подписываться на часть
  • ✗React.memo на потребителе полностью предотвращает перерисовку при смене контекста
  • ✗Создавать объект value заново на каждом рендере — рекомендуемая практика
