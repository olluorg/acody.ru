Как валидировать формы на фронтенде?

JuniorБраузер и DOM
Ещё спрашивают так:
  • Нужна ли проверка на сервере, если есть на клиенте?
Коротко

Проверка на клиенте — для удобства (быстрая подсказка), на сервере — обязательно (клиент можно обойти). Встроенные атрибуты: required, minlength, pattern, min/max, типы email и url; в JS — Constraint Validation API или библиотека схем (Zod, Yup). Ошибки показывать рядом с полем текстом, связывать через aria-describedby, проверять при уходе с поля или отправке, а не на каждый символ; фокус переносить на первое поле с ошибкой.

  • Сообщение говорит, как исправить: «Пароль от 8 символов», а не «Неверно»
  • Не стирать введённое при ошибке
  • Одна схема проверки на клиенте и сервере — меньше расхождений

Подробно

Ошибка сервера (почта занята) тоже должна показываться у поля, а не общим «Что-то пошло не так».

Что хотят услышать

  • Клиент для удобства, сервер обязательно.
  • Встроенные атрибуты и схемы.
  • Понятные сообщения рядом с полем.

Проверьте себя

Один верный вариант. Подумайте, потом откройте ответ.

Показать варианты и ответ
  • ✗Достаточно проверки на клиенте — сервер может доверять данным
  • ✓Клиентская проверка — для удобства, серверная обязательна; ошибки текстом у поля с подсказкой, как исправить
  • ✗Показывать ошибку на каждый введённый символ — лучший UX
  • ✗При ошибке очищать форму
