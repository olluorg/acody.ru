Почему HTTP называют протоколом без состояния (stateless)?

JuniorHTTP, cookies и сессииSpring
Ещё спрашивают так:
  • Почему серверу нужны cookie?
Коротко

Каждый запрос HTTP независим: сервер не помнит предыдущие. Чтобы связать запросы одного пользователя, нужен явный механизм — cookie с идентификатором сессии или токен.

  • Сессия: данные на сервере, в cookie — только id
  • Токен: данные подписаны и лежат у клиента
  • Stateless упрощает масштабирование серверов

А ещё Keep-alive переиспользует соединение, но состояние не добавляет

Подробно

Отсутствие состояния относится к протоколу, а не к приложению: данные сервер, конечно, хранит, но не обязан помнить контекст предыдущего обращения. Именно поэтому появились cookie: браузер прикладывает их автоматически, и сервер узнаёт пользователя. Отсюда же берётся уязвимость к CSRF — раз cookie отправляется автоматически, чужой сайт может спровоцировать запрос от имени пользователя. Постоянное соединение (keep-alive) существует, но к состоянию отношения не имеет — это оптимизация транспорта.

Что хотят услышать

  • Смысл stateless.
  • Механизмы связывания запросов.

Частые ошибки

  • Путать отсутствие состояния в протоколе с отсутствием данных на сервере.
  • Считать, что каждый запрос обязательно открывает новое соединение.
