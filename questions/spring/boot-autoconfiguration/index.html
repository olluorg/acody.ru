Как работает автоконфигурация Spring Boot?

MiddleSpring Boot и ActuatorSpring BootSpring Boot >=2.7
Ещё спрашивают так:
  • Как Spring Boot понимает, какие бины создать?
  • Как переопределить автоконфигурацию?
Коротко

Spring Boot подключает классы автоконфигурации из списка META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports (до 2.7 — spring.factories). Каждая создаёт бины по условиям: есть ли класс на classpath, есть ли уже такой бин, задано ли свойство.

  • @ConditionalOnClass, @ConditionalOnMissingBean, @ConditionalOnProperty
  • Свой бин того же типа — и автоконфигурация отступает
  • Отчёт: --debug или /actuator/conditions

А ещё Исключить: @SpringBootApplication(exclude = ...) или spring.autoconfigure.exclude

Подробно

Механизм. @SpringBootApplication включает @EnableAutoConfiguration. Он загружает список классов автоконфигурации из всех jar на classpath: в Spring Boot 2.7+ — файл AutoConfiguration.imports, раньше — spring.factories. Каждый класс — обычная @Configuration (точнее @AutoConfiguration), но с условиями.

Условия:

  • @ConditionalOnClass(DataSource.class) — библиотека есть на classpath;
  • @ConditionalOnMissingBean — пользователь не определил свой бин;
  • @ConditionalOnProperty("spring.cache.type") — задано свойство;
  • @ConditionalOnWebApplication, @ConditionalOnBean и другие.

Пример: добавили spring-boot-starter-data-jpa — на classpath Hibernate и HikariCP; автоконфигурация создаёт DataSource из spring.datasource.*, EntityManagerFactory, менеджер транзакций. Объявили свой DataSource — @ConditionalOnMissingBean выключит стандартный.

Отладка: java -jar app.jar --debug печатает отчёт условий (какие конфигурации применены и почему нет), то же в /actuator/conditions.

Свой стартер — модуль с классом @AutoConfiguration и записью в AutoConfiguration.imports.
