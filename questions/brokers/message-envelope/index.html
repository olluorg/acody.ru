Какие поля обязательно закладывают в конверт (envelope) сообщения?

MiddleПроектирование событий
Ещё спрашивают так:
  • Какие метаданные должны быть в каждом событии?
Коротко

В конверт кладут: id события (для идемпотентности), тип и версию схемы, время события, источник, correlation/trace id и id агрегата.

  • id — дедупликация у потребителей
  • Версия схемы — эволюция формата
  • trace id — сквозная трассировка через брокер

А ещё Список получателей в событии — признак, что это скрытая команда

Подробно

Конверт с метаданными важнее красоты полезной нагрузки: без идентификатора нельзя дедуплицировать, без версии схемы нельзя развивать формат, без времени события невозможно отличить порядок наступления фактов от порядка доставки, без корреляции невозможно связать цепочку обработки в трассировке. Отдельно стоит различать время наступления события и время его публикации — они расходятся при повторах и задержках. Перечисление получателей внутри события противоречит самой идее публикации: издатель не должен знать подписчиков, иначе связность возвращается и добавление потребителя требует правки издателя.

Что хотят услышать

  • Обязательные поля и зачем каждое.
  • Чего в событии быть не должно.

Частые ошибки

  • Складывать метаданные вперемешку с бизнес-полями.
  • Указывать в событии, кто должен его обработать.
