Что делает настройка auto.offset.reset=earliest?

MiddleKafka ConsumerKafka
Ещё спрашивают так:
  • С какого места читает новый consumer group?
Коротко

auto.offset.reset действует, только когда у группы нет сохранённого offset (новая группа или offset удалён по сроку). earliest — читать с самого раннего доступного, latest — только новые, none — ошибка.

  • По умолчанию latest: новая группа пропустит всё, что было до её старта
  • Если сохранённый offset есть, настройка игнорируется
  • Offset группы удаляется через offsets.retention.minutes (7 дней) после неактивности

А ещё Перемотка вручную — kafka-consumer-groups.sh --reset-offsets

Подробно

Группа потребителей хранит свою позицию в __consumer_offsets. При старте потребитель продолжает с сохранённого offset. Настройка auto.offset.reset нужна для случаев, когда позиции нет:

  • новая группа читает топик впервые;
  • сохранённый offset удалён — группа была неактивна дольше offsets.retention.minutes (по умолчанию 7 дней);
  • сохранённый offset указывает на удалённые по retention данные.

Значения:

  • earliest — начать с самого старого доступного сообщения (вся история в пределах хранения);
  • latest (по умолчанию) — начать с конца: обрабатывать только новые;
  • none — бросить исключение, пусть решает приложение.

Ловушка: новый сервис с latest запускается после того, как события уже пошли, — и пропускает их. Для сервисов, которым важны все события, — earliest и идемпотентная обработка. Наоборот, для «живых» уведомлений старые события не нужны.

Ручная перемотка — kafka-consumer-groups --reset-offsets --to-datetime или --to-earliest при остановленной группе, например чтобы перечитать события после исправления бага.
