Что такое topic, partition и offset в Kafka?

JuniorKafka: topic, partition, offsetKafka
Ещё спрашивают так:
  • Как Kafka хранит сообщения?
Коротко

Топик — именованный поток сообщений. Партиция — упорядоченный журнал, часть топика. Offset — номер сообщения внутри партиции.

  • Партиции распределены по брокерам и реплицируются
  • Сообщения дописываются в конец партиции и не изменяются
  • Потребитель хранит свою позицию (offset) и может её перемотать

А ещё Порядок гарантирован только внутри партиции

Подробно

Топик — логическая категория сообщений: orders, payments. Топик делится на партиции — это единица параллелизма, хранения и порядка. Каждая партиция — журнал на диске брокера (набор сегментов), в который сообщения только дописываются.

Offset — монотонно растущий номер записи в партиции. Он идентифицирует сообщение вместе с номером партиции и служит позицией потребителя: группа потребителей фиксирует (commit) последний обработанный offset в служебном топике __consumer_offsets и при перезапуске продолжает с него.

Хранение — по политике: удаление старше retention.ms или после retention.bytes, либо compaction — остаётся последнее значение по каждому ключу. Чтение сообщений их не удаляет.

Распределение: партиции разнесены по брокерам кластера, у каждой есть лидер и реплики. Продюсер выбирает партицию по ключу (хеш), потребители группы делят партиции между собой.

Что хотят услышать

  • Определения топика, партиции, offset.
  • Партиция как журнал с дописыванием.
  • Offset как позиция потребителя и хранение по политике.

Частые ошибки

  • Считать offset глобальным номером в топике.
  • Думать, что прочитанные сообщения удаляются.
