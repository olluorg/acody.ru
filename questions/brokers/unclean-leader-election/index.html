Чем опасен unclean leader election (unclean.leader.election.enable=true) в Kafka?

MiddleРепликация KafkaKafka
Ещё спрашивают так:
  • Что жертвует unclean.leader.election.enable=true?
Коротко

Разрешает стать лидером отставшей реплике вне ISR, когда все реплики ISR недоступны. Партиция снова доступна, но подтверждённые сообщения теряются, а потребители могут увидеть «откат».

  • По умолчанию false — выбрана согласованность (CP)
  • true — доступность ценой данных (AP); допустимо для метрик и логов
  • Для бизнес-событий — только false

А ещё Это прямая иллюстрация CAP на уровне одного параметра

Подробно

Если все реплики ISR недоступны, при unclean.leader.election.enable=true лидером назначается реплика вне ISR, у которой может не быть последних сообщений — это выбор availability ценой потери данных (по сути нарушение C ради A в духе CAP). При false партиция остаётся недоступной, пока не вернётся реплика из ISR — выбор consistency. Для систем, где терять подтверждённые сообщения нельзя, держат false (это и есть дефолт в современных версиях).

Частые ошибки

  • Включать unclean election «чтобы не было простоев», не осознавая потерю данных.
  • Путать недоступность партиции с потерей кластера.
