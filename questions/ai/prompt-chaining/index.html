Когда разбивать задачу на цепочку вызовов модели вместо одного большого промпта?

MiddleПромпты и структурированный вывод
Ещё спрашивают так:
  • Что такое prompt chaining?
  • Чем цепочка вызовов лучше одного промпта?
Коротко

Цепочка — последовательность вызовов, где каждый решает одну подзадачу и передаёт структурированный результат следующему: извлечь факты → проверить → сформулировать ответ. Помогает, когда один промпт пытается делать много разного и путается, когда нужны промежуточные проверки кодом, когда шаги требуют разных моделей (дешёвая для классификации, сильная для ответа). Цена — больше вызовов и задержка. Решение — сравнение на наборе: качество, стоимость, время.

  • Каждый шаг можно оценивать и улучшать отдельно
  • Между шагами — валидация: схема, бизнес-правила
  • Независимые шаги выполняются параллельно

А ещё Улучшать промпт надо по разбору ошибок на наборе, а не по одному неудачному примеру

Подробно

Пример: ответ на претензию клиента.

  1. Классифицировать тему и срочность (маленькая модель, JSON).
  2. Извлечь номер заказа и требования клиента (схема).
  3. Получить данные заказа инструментом.
  4. Сформулировать ответ по шаблону и политике (сильная модель).
  5. Проверить ответ на запрещённые обещания (правила или судья).

Когда один промпт лучше: задача простая, шаги тесно связаны, задержка критична, а качество на наборе уже достаточное.

Итерации. Ошибки на наборе группируют по причинам, правят промпт или структуру цепочки и прогоняют весь набор заново, чтобы не сломать другие сценарии.

Что хотят услышать

  • Когда цепочка лучше одного промпта.
  • Структурированная передача и проверки между шагами.
  • Цена в вызовах и задержке.
  • Решение по замеру и улучшение по разбору ошибок.
