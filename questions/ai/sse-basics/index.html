Как получить потоковый ответ модели и показать его пользователю?

JuniorLLM в продакшене
Ещё спрашивают так:
  • Что такое Server-Sent Events?
  • Как включить stream в API модели?
Коротко

В запросе включают потоковый режим (stream), и API отдаёт ответ частями по протоколу Server-Sent Events: каждое событие — строка «data: {…}» с очередным фрагментом текста (delta). Клиент добавляет фрагменты к уже показанному тексту, а последнее событие сообщает причину остановки и расход токенов. Пользователь видит начало ответа через доли секунды вместо ожидания всего текста.

  • SDK провайдеров дают итератор по фрагментам — вручную разбирать SSE обычно не нужно
  • Ошибка может прийти посреди потока — интерфейс должен показать её, а не зависнуть
  • Markdown рендерят по мере поступления, учитывая незакрытые блоки

А ещё В браузере SSE принимают через fetch с чтением потока или EventSource

Подробно

Python (схематично):

stream = client.chat.completions.create(
    model=MODEL, messages=messages, stream=True)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="", flush=True)

Формат SSE:

data: {"delta": "При"}
data: {"delta": "вет"}
data: [DONE]

В интерфейсе: индикатор «печатает», кнопка «остановить», обработка обрыва, сохранение полного ответа после завершения.

Что хотят услышать

  • Потоковый режим и SSE.
  • Склейка фрагментов на клиенте.
  • Финальное событие с причиной остановки и токенами.
  • Обработка ошибок посреди потока.

Показать варианты и ответ
  • ✗Потоковый режим отдаёт весь ответ одним событием после генерации
  • ✓Включить потоковый режим: ответ приходит фрагментами по SSE, клиент добавляет их к тексту, финальное событие несёт причину остановки и токены
  • ✗Потоковый ответ стоит в два раза дороже обычного
  • ✗Для стриминга нужно открывать новое HTTP-соединение на каждый токен
