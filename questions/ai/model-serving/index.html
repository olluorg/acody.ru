Как внедрить ML-модель — пакетный расчёт или онлайн-сервис?

MiddleMLOps и модели в продакшене
Ещё спрашивают так:
  • Как задеплоить модель на FastAPI?
  • Чем batch-инференс отличается от онлайн-инференса?
Коротко

Пакетный расчёт (batch): по расписанию модель считает прогнозы для всех объектов и пишет их в таблицу (отток на завтра, рекомендации на сутки) — просто, дёшево, легко проверить. Онлайн-сервис: прогноз по запросу в момент действия пользователя (антифрод при платеже, ранжирование выдачи) — нужен, когда признаки появляются в моменте или нужна мгновенная реакция. Сервис обычно — FastAPI с загруженной при старте моделью в Docker-образе, с версией модели, проверкой входа, метриками задержки и ошибок.

  • Начинать с пакетного, если задача это допускает
  • Модель грузится один раз при старте, а не на каждый запрос
  • Признаки при обучении и в сервисе считаются одним кодом — иначе training-serving skew

А ещё Логируйте входы и прогнозы — без них нельзя ни мониторить дрейф, ни разбирать ошибки

Подробно

Пример сервиса:

from fastapi import FastAPI
from pydantic import BaseModel
import joblib

app = FastAPI()
model = joblib.load("model-2026-10-01.joblib")

class Features(BaseModel):
    tenure_days: int
    orders_30d: int

@app.post("/predict")
def predict(f: Features):
    p = model.predict_proba([[f.tenure_days, f.orders_30d]])[0, 1]
    return {"churn_proba": p, "model_version": "2026-10-01"}

Что ещё нужно: health-check, метрики p95 задержки, ограничение размера запроса, постепенная выкатка новой версии, откат на прошлую, логирование прогнозов с идентификатором версии.

Показать варианты и ответ
  • ✗Модель лучше загружать из файла при каждом запросе — так она всегда свежая
  • ✗Онлайн-сервис всегда лучше пакетного расчёта
  • ✓Пакетный расчёт, если прогнозы можно посчитать заранее, и онлайн-сервис (FastAPI в Docker), если нужен ответ в момент действия; модель грузится при старте, признаки считаются тем же кодом
  • ✗Логировать прогнозы модели не нужно
