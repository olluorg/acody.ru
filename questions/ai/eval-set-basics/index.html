Как собрать первый набор примеров для оценки LLM-функции?

JuniorОценка качества
Ещё спрашивают так:
  • С чего начать оценку качества LLM?
  • Что такое golden set?
Коротко

Взять реальные запросы пользователей (или примеры от заказчика, если продукта ещё нет), отобрать разнообразные: частые, редкие, сложные, запросы без ответа, попытки выйти за рамки. Для каждого записать ожидаемое поведение: правильный ответ, нужные факты, требуемый инструмент или отказ. Начать можно с 30–50 примеров и пополнять: каждая найденная ошибка становится новым примером.

  • Хранить набор в репозитории в простом формате (JSONL, таблица)
  • Ожидаемое поведение формулировать проверяемо: «в ответе есть срок 14 дней», а не «хороший ответ»
  • Не подгонять промпт под набор до полной точности — набор должен оставаться честной проверкой

А ещё Отметьте сценарий у каждого примера, чтобы видеть качество по сценариям

Подробно

Формат примера:

{"id": "ret-07", "scenario": "возврат",
 "input": "Можно вернуть кроссовки через месяц?",
 "expect": {"contains": ["14 дней"], "no_tool": true}}

Что включить:

  • типичные вопросы каждого сценария;
  • пограничные и неоднозначные;
  • вопросы, на которые ответа нет (ожидается «не знаю» или передача оператору);
  • опечатки, разговорный стиль;
  • попытки заставить нарушить правила.

Использование: прогон после каждого изменения промпта или модели, сравнение с прошлым результатом.

Что хотят услышать

  • Реальные и разнообразные примеры.
  • Проверяемое ожидаемое поведение.
  • Пополнение набора ошибками.
  • Прогон при изменениях.
