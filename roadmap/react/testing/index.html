Тестирование React

Основа с Junior

Testing Library, тесты хуков и сквозные сценарии.

Компоненты тестируют как пользователь: найти кнопку по роли и подписи, нажать, проверить видимый результат. Внутреннее состояние и число рендеров не проверяют.

render(<Counter />);
await userEvent.click(screen.getByRole("button", { name: /нажато/i }));
expect(screen.getByRole("button")).toHaveTextContent("Нажато 1");

Что важно знать

  • Стек: Vitest (или Jest) + React Testing Library + user-event.
  • Сеть — через MSW: те же обработчики работают в тестах и в разработке.
  • Компоненты с провайдерами (роутер, кэш запросов, тема) — общая функция renderWithProviders.
  • Хуки — renderHook.
  • Сквозные сценарии — Playwright.

Темы этапа

  • Юнит-тесты и тесты компонентов Основа

    Vitest и Testing Library — проверять поведение, а не реализацию.

  • Сквозные тесты — Playwright Основа

    Сценарии в настоящем браузере — вход, оформление заказа, оплата.

Критерии освоения

Junior ≈ 4 ч

  • Тестирует компоненты через Testing Library и user-event

Практика. Покрыть тестами 3 компонента приложения.

Middle ≈ 4 ч

  • Тестирует компоненты с провайдерами и сетью через MSW, хуки — через renderHook

Практика. Сделать общую функцию renderWithProviders и покрыть тестами страницу с загрузкой данных.

Проверка знаний

Войдите, чтобы пройти тест: сданный тест отмечает тему пройденной на карте и в ИПР.

Вопросы с собеседований

  • Как тестировать React-компоненты через Testing Library и user-event? Junior

    Testing Library проверяет компонент как пользователь: рендерит его, ищет элементы по роли, подписи, тексту, а не по классам и внутреннему состоянию. user-event имитирует реальные…

  • Чем отличаются getBy, queryBy и findBy в Testing Library? Junior

    getBy… — элемент должен быть сейчас, иначе ошибка. queryBy… — возвращает null, если элемента нет: для проверки отсутствия (expect(queryByText("Ошибка")).not.toBeInTheDocument())…

  • Что тестировать во фронтенд-приложении на React? Junior

    Тестировать поведение, важное пользователю: что показывается при разных данных (пусто, ошибка, загрузка, список), что происходит после действий (отправка формы, фильтр, удаление)…

  • Как тестировать компоненты, которые ходят в сеть и используют провайдеры? Middle

    MSW (Mock Service Worker) перехватывает запросы на уровне сети и отвечает заданными данными: компонент работает с настоящим fetch и клиентом, а тест управляет ответами — успех…

  • Как тестировать пользовательские хуки? Middle

    Хук нельзя вызвать вне компонента, поэтому используют renderHook из Testing Library: он рендерит служебный компонент и отдаёт result.current — текущее возвращаемое значение…

  • Как писать юнит-тесты на фронтенде (Vitest, Jest)? Junior

    Юнит-тесты проверяют логику без браузера: функции форматирования, расчёты, валидацию, редьюсеры, хуки. Vitest (быстрый, совместим с Vite) и Jest — похожий API: describe, it/test…

  • Как тестировать компоненты с Testing Library? Junior

    Принцип Testing Library: тестировать так, как пользуется человек. Компонент рендерят, ищут элементы по роли, подписи, тексту (getByRole('button', { name: 'Отправить' }))…
