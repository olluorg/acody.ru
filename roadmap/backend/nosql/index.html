NoSQL-хранилища

Основа с Middle

Документные, key-value, колоночные, поисковые и базы временных рядов — когда что выбирать.

семействопримерыдля чего
key-valueRedisкэш, сессии, счётчики, очереди
документныеMongoDBгибкая схема, документ целиком
колоночные аналитическиеClickHouseаналитика по миллиардам строк

поисковыеElasticsearch, OpenSearchполнотекстовый поиск

Что важно знать

  • Выбор — по паттерну доступа, а не по моде; PostgreSQL закрывает большинство задач.
  • Второе хранилище — это синхронизация данных и согласованность.

Критерии освоения

Middle ≈ 8 ч

  • Объясняет семейства NoSQL и выбирает хранилище под паттерн доступа
  • Использует Elasticsearch для полнотекстового поиска и понимает его согласованность

Практика. Добавить в сервис полнотекстовый поиск по товарам на Elasticsearch с синхронизацией из PostgreSQL.

Senior ≈ 6 ч

  • Обосновывает выбор хранилища для системы по нагрузке, согласованности и эксплуатации
  • Объясняет компромиссы CAP и PACELC на примерах конкретных баз

Практика. Для трёх сценариев (лента событий, каталог, метрики) выбрать хранилища и обосновать письменно.

Вопросы с собеседований

  • Что общего у большинства хранилищ, называемых NoSQL? Junior

    NoSQL — не «без SQL», а размен: жертвуют соединениями, произвольными запросами и частью гарантий ради горизонтального масштаба, гибкой модели или скорости.

  • Когда NoSQL база может быть лучше реляционной? Middle

    NoSQL выбирают под конкретный паттерн доступа: документы, читаемые целиком; доступ по ключу с огромной нагрузкой; запись временных рядов; горизонтальное масштабирование записи…

  • В кворумной системе из N реплик при каком условии чтение гарантированно увидит последнюю запись? Senior

    При W + R > N множества реплик записи и чтения пересекаются, и чтение увидит последнюю подтверждённую запись. N — реплик, W — подтверждений записи, R — опрошенных при чтении.

  • Что такое репликация данных? Junior

    Репликация — копии одних и тех же данных на разных узлах: отказоустойчивость, масштабирование чтения, данные ближе к пользователям. Разделение на непересекающиеся части — это…

  • Для чего Elasticsearch обычно используют в backend-системах? Middle

    Для полнотекстового поиска (морфология, опечатки, релевантность), фасетов и фильтров по многим полям, поиска по логам и аналитики. Обычно это модель чтения рядом с основной базой…

  • Что добавляет PACELC к формулировке CAP? Senior

    CAP говорит только про сбой; PACELC добавляет: иначе (Else), без разделения, выбираем между задержкой (Latency) и согласованностью (Consistency).

Разборы темы

  • Документоориентированные БД (MongoDB)

    Модель документа, embedding против referencing, индексы, aggregation pipeline, атомарность документа и шардирование.

  • Полнотекстовый поиск (Elasticsearch)

    Почему LIKE не поиск, инвертированный индекс, анализаторы, релевантность BM25, query vs filter context и поиск как read model.

  • Key-value хранилища

    Простейшая модель доступа по ключу, типичные применения, Redis против DynamoDB, партиционирование и ограничения.

  • NoSQL: семейства и когда их выбирать

    Почему появился NoSQL, моделирование от access patterns, четыре семейства хранилищ, BASE против ACID и горизонтальное масштабирование.

  • Базы данных временных рядов

    Чем особенны time-series, модель measurement/tags/fields, сжатие и chunking, downsampling/retention и когда хватит обычной БД.

  • Колоночные БД: wide-column и аналитические

    Разница между wide-column (Cassandra) и column-oriented OLAP (ClickHouse), partition/clustering keys, LSM-дерево и зачем хранить по колонкам.
