Работа с API моделей

Основа

Сообщения и роли, потоковая выдача, структурированный вывод, лимиты и обработка ошибок.

Почти все провайдеры дают похожий интерфейс: список сообщений с ролями (system, user, assistant), параметры генерации, ответ с текстом и расходом токенов. Многие совместимы с форматом OpenAI, поэтому переключиться между провайдерами можно сменой адреса и ключа.

resp = await client.chat.completions.create(
    model="...",
    messages=[
        {"role": "system", "content": "Ты помощник службы поддержки магазина."},
        {"role": "user", "content": question},
    ],
    temperature=0.2,
)
print(resp.choices[0].message.content, resp.usage.total_tokens)

Модель не помнит прошлые запросы: история диалога каждый раз отправляется целиком, и за неё платят снова.

Вопросы с собеседований

  • Как реализовать потоковую выдачу ответа LLM пользователю? Middle

    Модель генерирует ответ токен за токеном, и его можно показывать по мере генерации: воспринимаемая задержка падает с десятков секунд до времени первого токена. Провайдеры отдают…

  • Как получить от LLM ответ в строгом формате, например JSON? Middle

    Используйте режим структурированного вывода по JSON-схеме, если API его поддерживает, и всегда валидируйте результат в коде.
