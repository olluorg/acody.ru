Структура большого приложения

Основа с Middle

Деление по функциональности, границы модулей, направление зависимостей, Feature-Sliced Design.

Что важно знать

  • По функциональности: модуль «корзина» содержит свои компоненты, хуки, запросы и типы.
  • Публичный API модуля — только через index.
  • Зависимости в одну сторону: страница → фича → сущность → общее.
  • Feature-Sliced Design — готовая методология со слоями app, pages, widgets, features, entities, shared.
  • Проверка автоматикой — eslint-правила границ.
  • По размеру: для небольшого приложения сложная архитектура — лишние затраты.

Критерии освоения

Middle ≈ 6 ч

  • Организует код по функциональности, а не по типу файлов, с публичным API модулей
  • Не допускает циклических зависимостей между модулями

Практика. Переструктурировать учебный проект по функциональности, оставить импорт модулей только через публичный index.

Senior ≈ 8 ч

  • Проектирует архитектуру приложения для нескольких команд и обосновывает её масштабом
  • Внедряет автоматическую проверку границ модулей в линтере

Практика. Описать архитектуру фронтенда продукта (слои, границы, состояние, правила зависимостей) в design doc и включить проверку границ в CI.
