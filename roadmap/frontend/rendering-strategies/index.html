Серверный рендеринг и мета-фреймворки

Основа с Middle

CSR, SSR, SSG и гидратация — где и когда собирается HTML; Next.js и аналоги.

Где собирать HTML — один из главных архитектурных выборов во фронтенде.

стратегиякакплюсыминусы
CSRпустой HTML, всё рисует JS в браузерепросто, дешёвый хостингмедленный первый показ, слабее SEO
SSRHTML собирается на сервере на каждый запросбыстрый первый показ, SEOнужен сервер, нагрузка
SSGHTML собирается при сборкемаксимально быстро, CDNданные устаревают до пересборки
ISRстатические страницы пересобираются по расписаниюкомпромисссложнее кэширование

Гидратация — браузер получает готовый HTML и «оживляет» его, навешивая обработчики. До её окончания страница видна, но не реагирует.

Что важно знать

  • Next.js (React), Nuxt (Vue), SvelteKit, Astro — мета-фреймворки с маршрутизацией по файлам, SSR и SSG.
  • Серверные компоненты React выполняются только на сервере и не отправляют свой код в браузер.
  • Ошибки гидратации: HTML сервера не совпал с первым рендером клиента (даты, Math.random, window при рендере).
  • Выбор: личный кабинет за логином — CSR достаточно; публичные страницы для поиска — SSR или SSG.

Критерии освоения

Middle ≈ 8 ч

  • Объясняет CSR, SSR, SSG, ISR и гидратацию и выбирает стратегию для страницы
  • Исправляет ошибки гидратации

Практика. Сделать на Next.js сайт, где лендинг статический, каталог пересобирается по времени, а личный кабинет рендерится на клиенте.

Senior ≈ 6 ч

  • Проектирует рендеринг продукта — какие страницы как рендерятся, кэширование и нагрузка на сервер

Практика. Описать стратегию рендеринга и кэширования для интернет-магазина с оценкой нагрузки на сервер.
