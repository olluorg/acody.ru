Архитектура фронтенда

Основа

Структура большого приложения, дизайн-системы, монорепозитории, микрофронтенды и frontend system design.

Пока приложение маленькое, архитектура почти не важна. Когда над ним работают десятки людей и сотни экранов, от неё зависит скорость команды: можно ли поменять одну функцию, не сломав три другие, быстро ли новичок находит нужный код, не тормозит ли сборка.

Это зона senior-фронтендера: на собеседованиях её проверяют секцией frontend system design («спроектируйте ленту», «спроектируйте автодополнение») и вопросами о структуре проектов, дизайн-системах и миграциях.

Темы этапа

  • Структура большого приложения Основа

    Деление по функциональности, границы модулей, направление зависимостей, Feature-Sliced Design.

  • Дизайн-системы Основа

    Токены, библиотека компонентов, Storybook, доступность и версии.

  • Frontend system design Основа

    Проектирование интерфейса целиком — требования, компоненты, данные, производительность, доступность.

  • Монорепозитории и микрофронтенды Полезно знать

    Как масштабировать фронтенд на много команд — общие пакеты, Nx и Turborepo, Module Federation.
