Работа с сетью — fetch и REST

Основа с Junior

Запросы к серверу из браузера — fetch, JSON, обработка ошибок, отмена, CORS.

async function loadOrder(id, signal) {
  const res = await fetch(`/api/orders/${id}`, { signal, headers: { Accept: "application/json" } });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);   // fetch не бросает на 4xx/5xx
  return res.json();
}
const ctrl = new AbortController();
loadOrder(42, ctrl.signal);
ctrl.abort();   // например, при уходе со страницы

Что важно знать

  • fetch отклоняет промис только при сетевой ошибке; коды 4xx и 5xx нужно проверять через res.ok.
  • Отправка JSON: method: "POST", body: JSON.stringify(data), заголовок Content-Type: application/json.
  • CORS: запрос на другой домен браузер разрешит, только если сервер ответил нужными заголовками; «непростые» запросы предваряются preflight OPTIONS. Это защита браузера, а не сервера.
  • Cookies на другой домен — credentials: "include" и согласие сервера.
  • Состояния загрузки и ошибки, повторы с паузой, гонки ответов (старый ответ пришёл позже нового) — отмена через AbortController.
  • В приложениях серверное состояние обычно ведут библиотеки вроде TanStack Query: кэш, повторы, обновление в фоне.

Критерии освоения

Junior ≈ 6 ч

  • Делает запросы через fetch, проверяет res.ok и показывает состояния загрузки и ошибки
  • Объясняет CORS и почему ошибка CORS — настройка сервера

Практика. Сделать страницу, которая загружает данные из публичного API с состояниями загрузки, пустого результата и ошибки.

Middle ≈ 4 ч

  • Отменяет запросы при уходе со страницы и обрабатывает повторы и таймауты
  • Работает с cookies на другом домене и понимает preflight

Практика. Написать обёртку над fetch с таймаутом, повтором, отменой и типизацией ответа.

Вопросы с собеседований

  • Что такое CSRF и как он связан с CORS? Middle

    CSRF — чужой сайт заставляет браузер жертвы отправить запрос на ваш сайт; браузер сам приложит cookie, и запрос выполнится от имени пользователя. CORS — правила, когда скрипт с…

  • Какие HTTP-методы вы знаете? Чем GET отличается от POST? Junior

    GET — получить данные, POST — создать или отправить, PUT — заменить целиком, PATCH — изменить частично, DELETE — удалить.

  • Какие изменения REST API обратно совместимы для существующих клиентов? Middle

    Добавлять можно (новое необязательное поле в ответе, новый эндпоинт, новый необязательный параметр); удалять, переименовывать, менять тип и ужесточать — нельзя.
