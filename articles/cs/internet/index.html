Как работает интернет — от адреса в браузере до ответа

Что происходит после нажатия Enter, слои сети и стек TCP/IP, TCP и UDP, как работает DNS и как проверять записи.

Что происходит после Enter

  1. DNS превращает имя shop.example.ru в IP-адрес.
  2. TCP-рукопожатие устанавливает соединение с сервером.
  3. TLS-рукопожатие договаривается о шифровании (для HTTPS).
  4. Браузер отправляет HTTP-запрос.
  5. На сервере запрос проходит балансировщик, веб-сервер, приложение, кэш и базу.
  6. Приходит ответ, браузер разбирает HTML, догружает CSS, JavaScript и картинки и рисует страницу.

Каждый шаг — минимум один оборот по сети. Поэтому так важны кэш DNS, повторное использование соединений (keep-alive) и CDN рядом с пользователем. На собеседовании глубину выбирают по вакансии: бэкендеру — подробнее про сервер, фронтендеру — про рендеринг.

Слои сети

Сеть устроена слоями: каждый решает свою задачу и пользуется нижним. OSI — учебная модель из семи уровней, на практике работает TCP/IP из четырёх:

СлойПротоколыЗадача
КанальныйEthernet, Wi-Fiкадры между соседями по MAC-адресам
СетевойIPпакеты между любыми узлами через маршрутизаторы
ТранспортныйTCP, UDPдоставка между процессами по портам
ПрикладнойHTTP, DNS, gRPCсмысл сообщений

«L4» и «L7» в описании балансировщиков — номера уровней OSI: транспортный и прикладной.

TCP и UDP

TCP — надёжный упорядоченный поток байтов с установкой соединения: рукопожатие, подтверждения, повторная передача, порядок, управление потоком и перегрузкой.

UDP — отдельные датаграммы без гарантий: нет соединения, повторов и порядка, зато быстро и просто. Его выбирают там, где потерянное уже устарело — голос, видео, игры, — и где запрос маленький, как в DNS.

QUIC, на котором работает HTTP/3, строит надёжность поверх UDP, чтобы обойти ограничения TCP.

DNS

DNS — распределённая иерархическая база «имя → адрес». Рекурсивный резолвер спрашивает по цепочке: корневые серверы → серверы зоны .ru → авторитетный сервер домена. Ответы кэшируются в браузере, ОС и резолвере на время TTL.

ЗаписьЧто хранит
A, AAAAIPv4- и IPv6-адрес
CNAMEпсевдоним другого имени
MXпочтовый сервер
TXTпроизвольный текст, проверки владения
NSкакие серверы отвечают за зону

Как проверить DNS

dig shop.example.ru              # A-запись и оставшийся TTL
dig shop.example.ru MX +short    # только ответ
dig @8.8.8.8 shop.example.ru     # спросить конкретный резолвер
dig +trace shop.example.ru       # цепочка от корня

Разные ответы у разных резолверов — где-то в кэше старое значение, ждите TTL. NXDOMAIN — домена нет; пустой ответ — нет записи такого типа. nslookup делает то же попроще и есть в Windows.

Переезд без простоя

Резолверы держат запись до истечения TTL, поэтому смена адреса не мгновенна. План:

  1. Заранее, не позже чем за текущий TTL, понизить TTL до минут.
  2. Поднять новый сервер и проверить его напрямую.
  3. Сменить запись.
  4. Держать старый сервер, пока по логам не уйдёт трафик, — некоторые резолверы игнорируют TTL.
  5. Вернуть TTL обратно.

Что запомнить

  • DNS → TCP → TLS → HTTP → сервер → ответ → рендеринг.
  • TCP — надёжность и порядок, UDP — скорость без гарантий.
  • DNS кэшируется на время TTL — перед переездом его снижают.
  • dig показывает и запись, и сколько она ещё проживёт в кэше.
